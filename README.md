# 커튼 명장 마스터즈

공간별 치수를 입력하고 커튼 스타일을 추천받아, 견적 요청서를 저장·다운로드한 뒤 제휴 상담으로 연결하는 한국어 사이트입니다. Next.js App Router, TypeScript, React를 사용합니다.

## 로컬 실행

Node.js 22 LTS와 npm을 사용하세요. SQLite 네이티브 모듈은 실행할 운영체제에서 설치합니다.

```sh
npm ci
cp .env.example .env.local
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다. 서버는 `127.0.0.1`에 바인딩됩니다. 로컬 검토 상태에서는 검색 노출이 차단됩니다.

다른 포트를 쓰려면 `.env.local`의 `NEXT_PUBLIC_SITE_URL`도 같은 포트로 바꾸고 `npm run dev -- -p 3001`처럼 실행하세요. 개발 환경에서는 같은 포트의 `localhost`와 `127.0.0.1`을 모두 허용합니다.

```sh
npm run typecheck
npm run format:check
npm test
npm run build
npm run start
```

`npm test`는 Node 테스트 러너와 `tsx` 로더를 사용합니다. 개별 확인은 `node --import tsx --test tests/analytics.test.ts`처럼 실행할 수 있습니다.

`npm run format`은 Prettier로 소스·설정·콘텐츠의 서식을 정리합니다. 생성물, 이미지·글꼴, 로컬 데이터와 환경변수 파일은 제외합니다. 서식만 검사하려면 `npm run format:check`를 사용하세요.

프로덕션 빌드의 실제 관리자 HTTP 흐름은 아래의 선택 테스트로 확인합니다. 별도 `127.0.0.1:3004` 서버·임시 DB·일회용 자격증명을 생성하고 종료하며 `.env.local`은 수정하지 않습니다. 포트가 사용 중이면 `ADMIN_HTTP_PORT`를 다른 빈 포트로 지정하세요.

```sh
npm run build
ADMIN_HTTP_FIXTURE=true ADMIN_HTTP_PORT=3004 node --import tsx --test tests/admin-http.test.ts
```

이 테스트는 관리자 로그인·권한·CSV·no-store·Secure 쿠키·로그아웃과 standalone의 실제 포스트 파일 추적을 확인합니다. 기본 `npm test`에서는 서버를 띄우지 않고 이 항목을 건너뜁니다.

## 고객 기능

- **홈 도우미:** 공간·가로·세로 입력 → 용도·분위기 선택 → 추천 결과. 단위는 cm이며 창문 자체/설치 범위, 실측/대략을 구분합니다.
- **여러 공간:** 공간과 창을 추가하고 창 크기에 비례한 그림을 확인합니다. 추천 이유·대안·상담 확인사항을 제공합니다.
- **로컬 저장:** 작성 중 자동 저장, 도우미 내부 ‘저장한 견적’에서 문서 선택·열기·수정·이름 변경·복제·삭제. 입력 내용은 해당 브라우저의 localStorage에만 남습니다.
- **PDF:** 금액 없는 견적 요청서. 공간별 치수, 추천 구성, 상담 준비사항, 작성일과 제휴 신청 링크를 포함합니다. PDF 코드와 한글 글꼴은 요청할 때 불러옵니다.
- **즉시 문의:** 저장·다운로드 없이도 제휴 신청 페이지로 이동합니다. 요청서 내용은 외부 양식에 자동 입력되지 않습니다.

실제 제작 치수·원단 성능·설치 가능 여부·가격은 제휴업체 상담에서 확정해야 합니다. 사이트의 스타일 이미지는 선택을 돕는 예시이며 실제 시공 사례나 시공 보증으로 표시하지 않습니다.

브라우저 데이터를 지우거나 기기·브라우저·도메인을 바꾸면 기존 로컬 문서를 사용할 수 없습니다. 저장이 차단된 환경에서도 현재 입력과 PDF 기능은 유지됩니다. 핵심 안내 본문과 직접 문의 링크는 JavaScript 없이도 제공되며, 도우미·보관함·PDF에는 JavaScript가 필요합니다.

## 화면과 스크롤

전역 헤더는 [Oracle](https://www.oracle.com/)의 좌측 메뉴·브랜드 배치를 참고해, 왼쪽 햄버거와 MASTERS. 브랜드명, 오른쪽 견적 문의로 정리했습니다. 메뉴 안에는 견적 도우미·커튼 가이드·서비스 안내만 표시합니다. 헤더 높이는 데스크톱 84px, 모바일 64px이며 스크롤과 함께 화면 밖으로 이동합니다. 첫 장면만 헤더를 제외한 높이를 쓰고, 다음 장면부터는 화면 전체 높이를 사용합니다. 저장 견적은 도우미 하단 버튼에서 열고 닫으며, 기존 `/saved` 주소는 `/?view=saved#helper`로 이동해 같은 화면을 엽니다.

홈은 **견적 준비 → 도우미 → 공간별 선택** 순서입니다. 최신 요구는 첫 장면과 도우미를 모두 간결하게 만드는 것입니다. 첫 장면에는 “커튼이 처음이라면, 여기부터.” 제목, 짧은 설명, **크기 입력 → 취향 선택 → 맞춤 추천**의 세 단계만 표시합니다. **내 커튼 찾기**는 도우미로, 보조 링크인 **커튼 가이드**는 안내 페이지로 연결합니다. 이전의 안내 박스·긴 설명·세로 준비 목록을 유지하던 기준은 이 요구로 변경됐습니다.

첫 배경은 화면을 채우는 움직이는 쉬폰 커튼 영상입니다. 실제 3,840 × 2,160 원본을 바탕으로 데스크톱 2,880 × 1,620, 모바일 1,080 × 1,920 파일을 제공합니다. 첫 장면의 카드 테두리와 흰 면을 제거하고 큰 제목·설명·주요 버튼·하단 이용 순서로 위계를 정리했습니다. 글 뒤의 밝은 그라데이션은 데스크톱 왼쪽에 한정해 오른쪽 영상을 가리지 않으며, 모바일도 글을 수직 중앙에 놓고 그 뒤를 중심으로 밝은 그라데이션을 적용합니다. 화면 폭과 높이에 맞춰 여백과 간격을 조절하며, 첫 장면의 글과 버튼을 한 화면에 표시합니다. 포스트 본문은 최대 760px입니다.

도우미는 **공간·크기 입력 → 용도·분위기 선택 → 추천 결과**의 세 화면으로 단순화했습니다. 측정 기준과 치수 정확도는 첫 화면에서 함께 선택합니다. 공간·창 관리와 상세 설명은 필요할 때 열고, 결과에서 문의·보관함 저장·PDF 다운로드에 바로 접근합니다. 여러 공간과 창의 데이터, 자동 저장과 기존 문서는 유지합니다. 모바일 공간별 가이드는 사진·제목·설명이 나란한 세 카드 행입니다.

홈은 브라우저 표준인 CSS Scroll Snap으로 장면을 정렬합니다. 데스크톱·태블릿·모바일 모두 `y mandatory`와 `scroll-snap-stop: always`를 사용합니다. 이동 속도와 관성은 브라우저가 처리하므로 물리적인 휠 한 칸마다 반드시 한 장면씩 이동하는 방식은 아닙니다.

첫 장면의 콘텐츠는 헤더 아래 영역에서 수직 중앙에 놓입니다. 도우미와 마지막 장면은 화면 전체 높이를 쓰며, 스냅 정지 시 현재 표시된 콘텐츠와 마지막 버튼까지 한 화면 안에 들어오도록 배분합니다. 문서 자체를 스크롤하고 도우미 내부에는 별도 스크롤을 두지 않습니다. 추가 창이나 추천 내용이 섹션 높이를 계속 늘리지 않도록 현재 공간·창을 선택합니다. 마지막 공간별 가이드와 푸터는 하나의 장면으로 합쳐 함께 정렬합니다. 가이드 등 다른 페이지는 기존 독립 푸터를 사용합니다. 간결하게 바꾼 첫 장면은 1440 × 900, 1280 × 600, 768 × 720, 390 × 844, 375 × 667, 320 × 568, 844 × 390의 7개 화면 크기에서 콘텐츠 경계를 확인했습니다. 도우미의 세 기본 화면도 같은 7개 크기에서 검수했습니다. 320 × 568에서 긴 오류 두 개, 여러 공간·창 전환, 저장·PDF와 저장본 복원을 확인했고, 새 구성의 자동 테스트·SEO HTTP·빌드 검사를 통과했습니다. 현재 기준은 [홈 수정 기준](docs/home-first-section-brief.md), 상태별 결과는 [검증 기록](docs/verification.md)을 참고하세요.

도우미 텍스트 입력칸에 초점이 있을 때만 화면 키보드 사용을 위해 스냅을 해제합니다. 버튼과 단계 제목에 초점이 있어도 스냅은 유지됩니다. 모션 감소 설정에서는 스냅과 부드러운 앵커 이동을 모두 해제합니다. 홈의 HTML 존재 여부로 스타일을 한정하므로 가이드 등 다른 페이지는 일반 스크롤입니다. JavaScript 없이도 홈의 정렬·본문·링크를 사용할 수 있습니다.

휠·터치·키보드 이벤트를 가로채는 코드, 스크롤 타이머와 프레임 애니메이션, 장면 등장 효과는 사용하지 않습니다. 기존 `HomeStory` 컴포넌트와 `lib/home-story.ts`를 제거했으며 기본 레이아웃은 `app/globals.css`, 홈 스냅과 첫 장면은 `app/home.css`, 도우미와 공간별 가이드의 한 화면 배치는 `app/helper-fit.css`와 `app/spaces-fit.css`에서 관리합니다. 영상 재생 관리는 스크롤과 별개인 기존 `LoopVideo` 컴포넌트를 유지합니다.

### 커튼 이미지와 영상

첫 장면은 `public/videos/curtain-sheer-hd.mp4`를 사용하며, 모바일에서는 별도 세로 편집본과 같은 구도의 포스터를 선택합니다. 포스터는 서버 HTML에서 우선 로딩하고 영상은 화면에 가까워졌을 때 불러옵니다. 이전 저해상도 쉬폰 파일과 검토용으로 생성한 정지 이미지 `curtain-hero.webp`는 보관하지만 현재 홈에서 사용하지 않습니다.

첫 배경과 도우미의 린넨 영상은 공통 `LoopVideo` 컴포넌트를 사용합니다. 화면에 보이는 영상 하나만 음소거·인라인으로 반복 재생하며 화면 밖이나 숨겨진 탭에서는 멈춥니다. 영상 재생·정지 버튼과 ‘스타일 예시’ 배지는 전역에서 표시하지 않습니다. 모션 감소·데이터 절약 설정에서는 정지 이미지를 유지합니다. 자동재생 차단이나 로딩 실패도 정지 이미지로 처리합니다.

영상은 `public/videos/`, 정지 이미지는 `public/images/`에서 제공하며 외부 동영상 플레이어나 방문 시 제3자 미디어 요청을 사용하지 않습니다. 원본 출처·라이선스와 편집 정보는 [미디어 자산 기록](docs/media-sources.md)을 참고하세요. 배포 시 `public` 폴더의 영상도 함께 포함해야 합니다.

## 콘텐츠와 SEO 구조

| 목표 키워드         | 대표 URL                |
| ------------------- | ----------------------- |
| 맞춤커튼            | `/`                     |
| 커튼설치·커튼시공   | `/guides/installation`  |
| 커튼전문점·커튼업체 | `/guides/companies`     |
| 인테리어커튼        | `/guides/interior`      |
| 거실커튼            | `/guides/living-room`   |
| 침실커튼            | `/guides/bedroom`       |
| 신혼집커튼          | `/guides/newlywed-home` |

`/guides`는 전체 허브입니다. 6개 카테고리와 8개 초기 포스트를 포함합니다. 공개 본문·비교표·펼쳐보기는 서버 HTML에 존재하며, 메타태그가 본문을 대체하지 않습니다. 내부 이동은 Next.js 라우터를 사용하고 도우미에 필요한 React 상호작용만 클라이언트에서 활성화합니다.

### 포스트 추가

`content/posts/`에 영문 소문자·숫자·하이픈으로 된 이름의 `.md` 파일을 추가하세요. 파일명이 URL의 마지막 경로가 됩니다. 예: `bedroom-light-check.md`.

```yaml
---
title: '침실커튼, 아침빛이 들어오는 곳 확인하기'
description: '침실 창의 빛샘과 설치 조건을 짧은 체크리스트로 정리하세요.'
primaryKeyword: '침실커튼'
relatedKeywords: ['침실 암막', '커튼 빛샘']
category: 'bedroom'
ctaIntent: 'helper'
helperPreset: 'bedroom'
relatedPosts: ['bedroom-blackout', 'measurement-basics']
date: '2026-09-05'
---
```

그 아래에 Markdown 본문을 작성합니다. 제목·짧은 설명·비교 항목·체크리스트처럼 실제로 읽을 수 있는 내용을 사용하세요.

- `category`: 위 표의 6개 카테고리 슬러그 중 하나입니다.
- `ctaIntent`: `helper`는 도우미, `apply`는 제휴 문의로 연결합니다.
- `helperPreset`: `living`, `bedroom`, `newlywed`, `other` 중 하나입니다. 기존 작성 내용은 링크의 시작 조건으로 덮어쓰지 않습니다.
- `relatedPosts`: 실제로 존재하는 포스트의 파일명에서 `.md`를 뺀 값입니다.
- `date`: 실제 발행·수정일을 `YYYY-MM-DD` 형식으로 기록합니다. 수정 시 날짜와 내용이 일치하게 관리하세요.

새 포스트는 카테고리 목록·사이트맵·자체 통계의 허용 경로에 자동 반영됩니다. 통계 경로 목록은 같은 Markdown의 신뢰된 파일명과 카테고리만 읽고, 요청마다 본문을 렌더링하지 않습니다. 개발 중 경로 목록은 최대 2초 후 갱신되며 운영에서는 **콘텐츠 변경 후 재빌드·재시작**합니다.

카테고리 자체를 추가하는 경우 `lib/content.ts`의 화면 정의와 `lib/analytics-server.ts`의 `CATEGORIES`를 함께 갱신하세요. `npm test`와 `npm run build`로 잘못된 관련 글·메타데이터·경로를 확인합니다.

## 관리자 통계

```sh
npm run admin:setup
```

대화형 터미널에서 비밀번호를 두 번 입력합니다. 입력 문자는 표시되지 않습니다. 생성된 `ADMIN_PASSWORD_HASH`와 `ADMIN_SESSION_SECRET`을 `.env.local`에 저장하고 서버를 재시작하세요. 생성값은 자격증명이므로 Git·공개 로그·메신저에 올리지 마세요. 설정 전에는 `/admin`과 CSV 내보내기가 잠겨 있습니다.

관리자는 `/admin`에서 로그인합니다. 로그인 세션은 8시간이며, 운영 환경에서는 HTTPS의 Secure·HttpOnly·SameSite 쿠키를 사용합니다. 설정 방법과 배포 옵션은 [배포 안내](docs/deployment.md)를 참고하세요.

통계는 SQLite에 저장되며 180일을 보관하고, 한 번에 최대 90일을 **UTC 날짜 기준**으로 조회합니다. 오래된 기록은 저장소에 접근할 때 하루에 한 번 정리됩니다. 페이지·카테고리·버튼·유입 구분별 이벤트 수와 세션 기반 도우미 전환 흐름, 일별 집계 CSV를 제공합니다.

### 측정 범위

| 항목                  | 실제 의미                                                   |
| --------------------- | ----------------------------------------------------------- |
| 페이지 조회           | 브라우저의 페이지 진입·SPA 경로 이동 이벤트                 |
| 도우미 시작·결과 확인 | 사용자가 해당 도우미 단계를 수행한 기록                     |
| 요청서 저장           | 브라우저의 문서 보관 동작                                   |
| PDF 생성 성공         | PDF 생성 동작의 성공; 실제 디스크 저장 여부는 알 수 없음    |
| 제휴 문의 이동        | 서버가 받은 `/go/quote` 요청; 외부 신청 완료가 아님         |
| 도우미 전환 흐름      | 같은 익명 세션의 시작 → 결과 → 문의 이동 순서를 만족하는 수 |

브라우저 이벤트는 UUID로 중복을 제거하고 제한된 재전송 큐를 사용합니다. 새로고침·재전송의 중복과 SPA의 이중 실행을 줄이지만, 차단 확장 프로그램·네트워크 오류·큐 만료·자동 트래픽 때문에 누락이나 왜곡이 생길 수 있습니다. GA4보다 항상 정확하다고 보장하지 않습니다. 익명 세션은 sessionStorage를 사용하므로 여러 기기·브라우저를 하나의 고객으로 합치지 않습니다.

유입은 `document.referrer`를 `direct`, `google`, `naver`, `external`, `internal`로 구분합니다. 원본 URL·검색어·UTM 전체를 저장하지 않습니다. 문의 이동은 같은 세션의 첫 출처 기록을 참고하며, 기록이 없거나 JavaScript 없이 이동한 경우 출처가 미지정일 수 있습니다. **목표 키워드는 실제 유입 검색어가 아닙니다.** 검색 노출·클릭·검색어는 Search Console과 네이버 서치어드바이저에서 별도로 확인합니다.

사이트 문의 링크는 서버 경유로 기록되지만 PDF 내부 링크는 제공된 제휴 URL로 직접 연결되어 클릭 통계에 포함되지 않습니다. 외부 신청·상담 완료는 제휴사의 공식 API·postback 연동이 제공되어야 추가할 수 있습니다.

## 데이터와 주요 코드

- `lib/quote.ts`, `lib/recommend.ts`: 문서 검증·로컬 저장 모델·설명 가능한 추천 규칙.
- `lib/pdf.tsx`: 브라우저 PDF 생성과 한글 글꼴 설정.
- `lib/content.ts`, `content/posts/`: 카테고리와 파일 기반 포스트.
- `lib/analytics-client.ts`, `lib/analytics-server.ts`: 브라우저 이벤트·허용 경로·집계·보관 정책.
- `lib/auth.ts`, `app/admin/`, `app/api/admin/`: 관리자 인증·통계·CSV.
- `lib/site.ts`: 브랜드·공개 도메인·고정 제휴 URL. 제휴 코드가 포함된 URL을 보존합니다.

앱 분석 DB에는 정확한 치수·문서 이름·본문·주소·연락처·원본 IP·전체 유입 URL을 넣지 않습니다. 공개 이벤트 API는 정해진 유형·경로·카테고리·버튼·출처만 받으며 서버 생성 시간으로 기록합니다. 관리자·저장 문서·이동 경로는 검색 대상에서 제외합니다. 고객 문서를 서버로 저장하거나 외부 업체에 자동 전송하는 API는 없습니다.

공개 전 설정, 영속 디스크, 백업, 검색 등록, 장애 확인은 [배포 안내](docs/deployment.md)에 정리했습니다.
