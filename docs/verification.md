# 구현 검증 기록

검증일: 2026-09-05. Node.js 22.18.0, Next.js 16.3.4, 로컬 개발 서버와 standalone 프로덕션 서버에서 확인했습니다.

## 자동 검사

- TypeScript와 Prettier 검사, 프로덕션 빌드.
- 입력값 검증: 빈 값, 0, 음수, 과도한 값, 십진수, 잘못된 숫자 표기.
- 요청서 스키마·복제·50개 한도. 한도 초과 시 기존 요청서를 제거하지 않습니다.
- 저장소 읽기 차단·손상 데이터·용량 초과에서 기존 기록과 현재 입력 보존.
- 추천 분기와 측정값이 암막 성능을 결정하지 않는 규칙.
- 전송 중 추가 이벤트 배출, 원래 유입 구분 유지, 이벤트 ID 중복 제거.
- 허용된 이벤트 필드·경로·카테고리만 수집, DB 실패에도 고정 제휴 주소로 이동.
- 관리자 인증·서명 변조·기간 제한·요청 출처 검사·CSV 문자 처리.
- 비공개/공개 환경별 robots·사이트맵·canonical·구조화 데이터.

실제 HTTP 검사는 별도로 실행했습니다. 홈페이지·허브·6개 카테고리·8개 포스트의 서버 HTML 16개를 확인했으며, 관리자 로그인·권한·집계 CSV·쿠키 속성·로그아웃을 임시 standalone 서버에서 확인했습니다. 이 서버의 임시 자격증명과 DB는 검사 후 정리했습니다.

## 브라우저 확인

데스크톱과 390px 모바일 화면에서 다음 흐름을 확인했습니다.

1. 빈 치수의 오류가 해당 입력칸 옆에 표시되고 첫 오류로 초점이 이동합니다.
2. 거실 360 × 240cm를 입력하고 암막·호텔 분위기를 선택하면 암막커튼이 추천됩니다.
3. 이름 지정·저장·복제·이름 변경·다시 열기가 동작합니다.
4. 저장본의 가로를 375.5cm로 수정한 직후 페이지를 이동하고 새로고침해도 최신값이 복원됩니다.
5. 안방 180 × 220cm를 추가하고 설치 범위·실측을 선택하면 공간별 정보가 유지됩니다. 안방의 숙면·모던 취향은 암막 롤 블라인드로 추천되며 거실 추천과 구분됩니다.
6. PDF 생성 완료 안내, 보관함의 저장 내용, 삭제 확인과 빈 보관함 표시를 확인했습니다.
7. 가이드 허브 → 거실 대표 페이지 → 포스트 → 도우미 연결을 확인했습니다.

모바일 입력은 숫자 키패드용 `inputmode="decimal"`을 사용합니다. 주요 터치 동작의 높이는 44px 이상으로 보완했습니다. 실제 모바일 기기의 키보드·다운로드 UI와 저성능 기기 반응 속도는 공개 전 대상 기기에서도 확인하는 것이 좋습니다.

## PDF·초기 로딩

- 한글 PDF 1페이지, 여러 공간 4페이지, 창 20개 2페이지 문서를 생성했습니다.
- 모든 페이지의 한글·줄바꿈·표·페이지 번호를 시각적으로 검토하고 치수와 제휴 링크를 추출해 확인했습니다.
- PDF 코드와 한글 글꼴은 다운로드를 누를 때 불러옵니다. 프로덕션 최초 HTML의 스크립트 목록에 PDF 청크·글꼴 경로가 포함되지 않는 것을 확인했습니다.
- 스타일 예시 사진은 약 68KB WebP이며 실제 시공 사례로 표시하지 않습니다.

로컬 검증은 실제 사용자 Core Web Vitals 또는 검색 순위를 측정한 결과가 아닙니다. 운영 도메인에서 모바일 LCP·INP·CLS와 방문 데이터를 확인해야 합니다.

## 쇼룸형 레이아웃 개편 확인

같은 검증일에 홈·가이드·포스트·보관함의 표시 구조와 여백을 개편했습니다. 데이터 형식과 API는 유지했습니다.

- 홈, 거실 카테고리, 거실 포스트를 1,440px·1,280px·768px·390px·320px 너비에서 검사했고 문서의 가로 넘침은 없었습니다. 320px 모바일의 헤더와 입력 카드, 390px 보관함도 시각적으로 확인했습니다.
- 390 × 640px의 짧은 화면에서 두 공간·세 창을 입력하고 측정 그림을 펼쳤습니다. 도우미는 내용에 따라 늘어나며 마지막 입력과 추천·문의·저장·PDF 버튼까지 접근할 수 있었습니다. 1,100 × 700px에서도 도우미가 잘리지 않고 푸터까지 이동했습니다.
- 모바일 목적 선택은 1열, 분위기는 이미지와 설명이 나란한 1열 카드, 공간과 가로·세로 입력은 2열입니다. 입력 라벨은 14px입니다.
- 홈의 입력 초점에서 스냅이 해제되고, 초점 해제 후 복구되는 것을 확인했습니다. 가이드·보관함에서는 스냅 속성이 제거됩니다. `#helper` 진입은 고정 헤더 아래 24px에 맞춰지며 저장본 열기·뒤로 가기에서 입력값이 유지됩니다.
- Tab 탐색의 초점 테두리, End 키의 푸터 접근, 추천·이름 지정·저장·PDF 생성 성공·저장본 열기·삭제를 확인했습니다. 제휴 문의는 기존 고정 중계 경로와 `rel="sponsored"`를 유지합니다. 외부 신청은 제출하지 않았습니다.
- 새 스크롤 제어 테스트 7개는 입력 초점, 모바일 키보드의 시각/레이아웃 뷰포트 축소, 데스크톱 크기 변경, 모션 감소 전환, 애니메이션 취소, 페이지 이탈 정리, 복원된 장면을 다룹니다. 모바일 키보드와 OS 모션 감소 설정은 자동 테스트의 모의 환경으로 검증했으며 실제 iOS·Android 기기 검증은 별도입니다.
- 포맷·타입 검사, 기본 테스트 43개, 프로덕션 빌드가 통과했습니다. 별도 HTTP SEO 검사로 공개 콘텐츠 16개 페이지의 서버 HTML·제목·canonical·구조화 데이터·CTA를 다시 확인했습니다. 기본 테스트에서 선택 HTTP 검사 2개는 건너뛰며, 관리자 HTTP 검사는 이번 표시 변경에서 재실행하지 않았습니다.

### 2026-09-06 화면 높이 보완

데스크톱 첫 장면의 제목·저장 상태를 사진 영역으로 옮기고, 입력의 추가 동작과 다음 버튼을 한 행으로 정리했습니다. 공간 사진은 가로 폭에 비례한 고정 높이 대신 장면의 남은 세로 공간을 사용합니다.

| 화면                   | 헤더 제외 높이 | 기본 홈의 세 장면 높이 |
| ---------------------- | -------------- | ---------------------- |
| 1024 × 720, 1280 × 720 | 624px          | 각 624px               |
| 1440 × 800             | 704px          | 각 704px               |
| 1440 × 900             | 804px          | 각 804px               |
| 1920 × 1080            | 984px          | 각 984px               |

1280 × 720에서 첫 단계의 다음 버튼, 공간 카드의 마지막 설명, 준비 장면의 가이드 버튼이 각각 화면 안에 표시됩니다. 768·390·320px에서도 가로 넘침은 없었습니다. 모바일은 읽기 크기를 유지한 자연 높이를 사용합니다. 측정 안내를 펼치면 첫 장면이 859px로 늘어나고 별도 내부 스크롤이나 잘림 없이 접근됩니다. 추천 확인·입력 수정·빈 초안 복원·가이드 이동 시 스냅 해제를 확인했습니다. 타입·포맷·43개 기본 테스트·프로덕션 빌드와 별도 16페이지 HTTP SEO 검사가 통과했습니다.

## 풀페이지 스크롤 최종 보완 · 2026-09-06

위 화면 높이 보완 이후, CSS 스냅을 실제 제스처 단위 전환으로 교체했습니다. 바깥 장면만 화면 높이를 채우고 내부 콘텐츠는 늘리지 않습니다. 1920 × 1080에서 기본 도우미 카드는 622px, 공간 사진은 380px입니다. 1440 × 900, 1280 × 720, 1024 × 720에서도 소개와 치수 그림이 겹치지 않으며 320px까지 가로 넘침이 없었습니다.

- 브라우저의 짧은 휠 제스처와 큰 휠 제스처가 각각 정확히 한 장면씩 이동했습니다. 1280 × 720에서 이동 위치는 0 → 624 → 1248px이며, 다음 동작은 푸터 끝으로 이어집니다. 푸터에서 위로 이동하면 마지막 장면으로 돌아옵니다.
- 측정 안내를 펼친 848px 장면에서는 먼저 문서가 약 224px까지 자연 스크롤되고, 같은 제스처로 다음 장면을 건너뛰지 않았습니다. 새 제스처에서만 다음 장면 시작으로 이동합니다.
- 입력 초점 중에는 작은 휠 이동이 일반 스크롤로 처리됩니다. PageDown·PageUp·Home, 도우미 앵커 진입, 가이드 페이지에서 제어 해제도 확인했습니다.
- 전용 테스트 18개는 트랙패드 관성·휠 단위·동적 높이·긴 장면 경계·푸터·키 반복·기본 컨트롤 동작·터치·핀치·모바일 키보드·모션 감소·전환 취소·초기 위치·정리를 다룹니다. 터치·실제 기기 키보드와 OS 모션 감소 동작은 모의 환경 검사이며 실제 iOS·Android 기기에서의 확인은 별도입니다.
- 타입·포맷·54개 기본 테스트·프로덕션 빌드와 공개 콘텐츠 16페이지 HTTP SEO 검사가 통과했습니다. 기본 테스트에서 선택 HTTP 검사 2개는 건너뛰고 SEO HTTP 검사는 별도로 실행했습니다. 추천·저장·PDF·API 데이터 형식은 변경하지 않았습니다.

## 홈 재배치와 루프 영상 · 2026-09-06

홈을 견적 준비 → 도우미 → 공간별 선택 순서로 변경했습니다. 첫 장면의 안내 박스가 준비 과정 위에 있으며 H1은 하나입니다. 도우미 제목은 H2로 유지하고 `#helper`와 저장본 열기 경로는 변경하지 않았습니다.

- 정확히 지정된 Pexels 영상 두 개를 로컬 8초 무음 루프로 제작했습니다. 데스크톱 파일은 약 505KB·1.02MB, 모바일은 224KB·467KB입니다. 전체 프레임 디코딩·오디오 제거·faststart·반복 경계와 포스터를 확인했습니다. 세부 결과와 재생성 명령은 [영상 자산 기록](media-sources.md)에 있습니다.
- 1440·1280·768·390·320px에서 기본 및 긴 추천 화면의 가로 넘침을 확인했습니다. 모바일 도우미 영상은 16:9이며 치수 미리보기 오버레이는 숨깁니다. 데스크톱의 소개·치수·저장 상태는 별도 그리드 행으로 배치해 긴 문구에도 겹치지 않게 했습니다.
- 1280 × 720px에서 휠 제스처마다 0 → 624 → 1248px로 이동하고, 다음 제스처는 푸터 1504px까지 이어졌습니다. PageUp으로 마지막 장면에 돌아오고 Home으로 첫 장면에 복귀했습니다. 모바일의 긴 입력과 결과는 내용에 맞춰 늘어납니다.
- 화면 전환 시 쉬폰 → 린넨으로 재생이 교대하며 공간별 선택에서는 두 영상 모두 멈췄습니다. 재생·정지 버튼, 모바일 파일 전환을 실제 브라우저에서 확인했습니다. 고정 헤더 뒤의 영상이 재생 대상으로 선택되는 문제도 수정·검증했습니다.
- 390px에서 두 공간·세 창을 입력하고 측정 안내를 펼쳤습니다. 침실의 암막·호텔 취향 추천, 320px의 문의·저장·PDF 버튼 접근, PDF 생성 성공, 저장본 열기와 뒤로 가기, 약 104px의 도우미 앵커 위치를 확인했습니다. 테스트용 저장본을 삭제하고 빈 초안으로 정리했습니다.
- 홈 이탈 시 영상 요소와 풀페이지 제어 속성이 제거됩니다. 서버 HTML 16페이지의 기존 SEO 검사에 홈 순서·단일 H1·정지 이미지·영상 지연 로딩·직접 문의 링크 검증을 추가했고 통과했습니다. 제휴 링크의 고정 경로와 `rel="sponsored"`를 확인했으며 외부 신청 양식은 제출하지 않았습니다.
- 영상 수명주기 테스트 15개는 단일 재생, 탭 숨김, 화면 이탈, 수동 정지 유지, 모션 감소·데이터 절약과 수동 재생, 자동재생 거절·파일 실패, 반응형 소스 교체, 늦은 재생 이벤트, 헤더 가림과 정리를 검증합니다. 모션 감소·데이터 절약·모바일 키보드는 모의 환경 검사이며 실제 iOS·Android 기기 확인은 별도입니다.
- 최종 타입·포맷 검사와 프로덕션 빌드가 통과했습니다. 기본 테스트는 69개 통과, 선택 HTTP 검사 2개 건너뛰기이며 공개 콘텐츠 16페이지 SEO HTTP 검사는 별도 실행해 통과했습니다.

## 브라우저 표준 스크롤 전환 · 2026-09-06

이 절부터 CSS Scroll Snap이 기존 제스처 단위 컨트롤러를 대체합니다. 위 기록의 제스처 임계값·타이머·고정 전환 시간과 관련 모의 테스트는 이전 구현의 이력이며 현재 스크롤의 동작 기준이 아닙니다.

- `HomeStory` 컴포넌트와 419줄의 `lib/home-story.ts`를 제거했습니다. 휠·터치·키보드를 가로채거나 스크롤 위치를 반복 보정하는 코드 없이 브라우저의 이동·감속을 사용하며, 장면 등장 애니메이션도 제거합니다.
- 홈의 문서 스크롤에만 CSS 정렬을 적용합니다. 1,024px 이상이고 `pointer: fine`인 경우 `y mandatory`와 장면의 `scroll-snap-stop: always`, 그 밖의 태블릿·모바일·터치 환경에서는 `y proximity`와 `normal`을 사용합니다. 헤더 높이는 루트의 `scroll-padding-top`에 한 번 반영하고 푸터도 정렬 대상으로 포함합니다.
- 도우미의 `:focus-within` 동안 스냅을 해제해 입력뿐 아니라 다음 단계의 제목 초점·버튼 조작도 일반 스크롤로 처리합니다. 모션 감소 설정에서는 스냅과 부드러운 앵커 이동을 해제합니다. 홈이 없는 경로에는 해당 규칙이 적용되지 않습니다.
- 장면은 화면을 최소 높이로 사용하며 긴 입력·펼쳐보기·결과의 높이를 제한하지 않습니다. 큰 정렬 영역 내부의 자유로운 이동과 브라우저가 결정하는 스크롤 물리는 [W3C CSS Scroll Snap 표준](https://www.w3.org/TR/css-scroll-snap-1/#snap-overflow)을 따릅니다. 물리적 휠 한 칸과 한 장면을 일대일로 대응시키는 보장은 하지 않습니다.
- 영상 재생과 정지 이미지 처리, 도우미 데이터 형식·API·제휴 경로·가이드 본문은 변경하지 않습니다. 기존 HTTP·SEO 검사 대상도 유지합니다.

이번 전환에서 확인한 결과:

- 1280 × 720px에서 홈의 `y mandatory`, 헤더 오프셋 96px, 장면 `start`/`always`가 적용됩니다. 기존 제어 속성은 없으며 일반 휠 이동으로 도우미 경계와 푸터에 접근했습니다. 작은 휠 이동은 현재 경계로 돌아올 수 있고 빠른 이동의 거리는 브라우저가 결정하므로, 휠 한 칸을 한 장면으로 강제하지 않습니다.
- 측정 설명과 두 번째 창을 추가한 약 1172px 도우미 내부에서 위치가 720 → 864px로 자연스럽게 이동했습니다. 별도 내부 스크롤이나 이전 위치로 강제 보정하는 동작은 없습니다.
- 입력·추가 버튼·단계 제목에 초점이 있는 동안 `scroll-snap-type: none`이며 첫 장면의 제목을 클릭해 초점을 벗어나면 다시 기본 정렬로 돌아왔습니다. `#helper`는 헤더 아래 약 98px에 표시됩니다. 단계 제목의 헤더 여백 중복도 제거했습니다.
- 768·390·320px에서 기본 스냅은 `proximity`, 경계 통과는 `normal`이며 가로 넘침이 없었습니다. 390px의 작은 휠 이동은 253px의 중간 위치에 머물 수 있어 긴 내용을 자유롭게 읽을 수 있습니다. 실제 기기 터치·OS 모션 감소는 이번 브라우저 환경에서 조작하지 않았으며 해당 CSS 분기를 확인했습니다.
- 가이드 진입 시 계산된 스냅은 `none`, 영상 요소는 0개입니다. 뒤로 가기 후 홈의 스냅과 작성 값이 복원됐고, 검증용 창·치수를 정리한 뒤 새로고침에서도 빈 초안을 확인했습니다. 영상 재생 교대는 유지됩니다.
- 타입·포맷·프로덕션 빌드와 기본 테스트 51개가 통과했습니다. 제거한 커스텀 스크롤 구현 전용 모의 테스트 18개도 함께 제거했습니다. 선택 HTTP 테스트 2개는 기본 실행에서 건너뛰며, 공개 콘텐츠 16페이지 SEO HTTP 검사는 별도 실행해 통과했습니다.

## 첫 섹션 비율·구성 개선 · 2026-09-06

첫 섹션의 흰 카드·테두리·그림자를 제거하고 제목·설명·주요 버튼을 영상 위에 직접 배치했습니다. 이용 순서는 버튼 아래의 가는 선과 세 항목으로 정리했습니다. 데스크톱은 왼쪽의 국소 그라데이션, 모바일은 위쪽에서 아래로 옅어지는 그라데이션을 적용합니다. 고화질 영상과 기존 문구·목적지는 유지합니다.

## 일반 헤더·모바일 스냅·마지막 푸터 병합 · 2026-09-06

- 기본 테스트 53개 통과, 선택 HTTP 2개 건너뜀. 공개 HTML 16페이지 HTTP 검사에서 모든 페이지의 푸터 1개, 홈 마지막 섹션 내부 푸터와 독립 푸터 부재, 기존 제목·영상·링크·canonical 검사가 통과했습니다. 타입·포맷·프로덕션 빌드를 확인했습니다. 브라우저 오류 로그는 없었습니다.
