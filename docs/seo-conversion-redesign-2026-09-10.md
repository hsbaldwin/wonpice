작성일: 2026-09-10 KST. 대상: 커튼 견적 도우미. 기존 공개 URL 19개를 유지하면서 홈의 일반 스크롤 구성, 검색 질문에 답하는 글, 상담 준비 문구 복사, 문의 진입점 및 계측 신뢰성을 개선했다.

### 홈과 상담 흐름

홈은 `main[data-home-content]` 아래 `home-intro`, `helper`, `home-spaces`, `home-essentials`, `home-process`, `home-faq`, `home-inquiry` 순서다. H1은 서버가 출력하는 첫 안내에 한 개만 있으며 도우미의 제목은 H2를 사용한다. 과거 `data-home-story`·`scene-*`를 전제로 하는 화면 높이·스크롤 제약은 현재 홈의 기준이 아니다.

치수를 모르는 방문자는 `home-hero`, `home-helper-direct`, `home-final`에서 바로 신청할 수 있다. 치수를 정리하려는 방문자는 `#helper`와 `/?room=...#helper`로 이동한다. 저장본 경로 `/saved`는 `/?view=saved#helper`로 이동한다. 결과 복사는 `home-result-copy`로 기록한다.

글 중간 CTA는 `post-middle`이다. 실측·원단·공간 선택 글은 도우미로 준비하는 동작을 앞에 두고, 견적·입주 준비 글은 신청을 앞에 둔다. 글 마지막 `post-bottom`은 신청을 기본 동작으로 제공한다. 복사 이벤트는 `post-copy`, 허브 마지막 신청은 `guide-hub-bottom`, 서비스 안내 마지막 신청은 `about-bottom`으로 구분한다. 기존 CTA 식별자는 호환성을 유지한다.

### Markdown과 복사 구현

`lib/content.ts`는 Markdown 전체 트리를 파싱한 뒤 `bodyBlocks`의 `html`, `visual`, `cta` 블록을 순서대로 생성한다. `<!-- visual: ID -->`와 `<!-- cta -->`는 독립 블록으로만 허용한다. 알 수 없거나 잘못된 마커, 같은 글의 중복 도해, 누락 이미지·미등록 자산, 누락된 직접 답변·상담 문구를 오류로 처리한다. 글마다 본문 CTA 한 개와 하나 이상의 도해가 필요하다.

H2의 목차 ID와 참조 링크는 블록 분리 후에도 유지한다. 비교표는 이름 있는 스크롤 영역과 키보드 초점을 제공하며 행 제목을 `th scope="row"`로 출력한다. 도해 루트는 `data-guide-visual`로 식별한다. 복사 문구는 읽기 전용 textarea에 서버 렌더링되어 JavaScript 실행 전에도 읽고 수동 복사할 수 있다.

`ConsultationCopy`는 `navigator.clipboard.writeText`가 실제로 성공했을 때만 성공 상태와 `consultation_copy`를 기록한다. 실패하면 textarea에 초점을 옮겨 선택하고 직접 복사하도록 안내한다. 처리 중 중복 클릭, 언마운트, 복사 도중 문구 변경으로 발생한 오래된 응답은 성공 표시와 계측을 갱신하지 않는다. 이벤트에 복사한 문구나 입력 치수·연락처·오류 텍스트를 보내지 않는다.

## 기술 SEO와 계측 보강

공개 빌드의 `SITE_INDEXABLE=true`에서는 `NEXT_PUBLIC_SITE_URL`에 HTTPS 도메인 원점이 필요하다. localhost·로컬 도메인·IP, 인증정보, 비표준 포트, 경로·쿼리·fragment 등 잘못된 값은 `lib/site.ts`에서 실패한다. 검토 빌드는 로컬 URL을 사용할 수 있으며 `noindex`, robots 전체 차단, 빈 sitemap을 유지한다.

공개 페이지는 완전한 페이지별 소셜 메타데이터를 제공한다. 글의 표지·Open Graph·Twitter·Article.image는 동일 자산이고 Article의 제목·설명·발행일·수정일·canonical이 콘텐츠와 일치해야 한다. 공개 sitemap에는 19개 URL만 포함하며 `/admin`, `/api`, `/go`, `/saved`는 포함하지 않는다. 쿼리 매개변수는 별도 canonical 페이지를 만들지 않는다.

분석 이벤트는 동일 `eventId`를 보존해 재시도하고 저장소에서 중복을 제거한다. 네트워크 및 서버 실패 시 2/4/8/16/30초 순서로 최대 5회 자동 재시도한다. `Retry-After`가 유효하면 우선 사용하되 60초를 넘지 않는다. 한 타이머만 사용하고 제한 이후 큐를 남겨 온라인·탭 복귀 시 재개한다. 큐는 최대 60개이며 브라우저 저장이 차단되어도 메모리에서 재시도한다. cleanup 이후 늦은 응답이 새 재시도 타이머를 만들지 않도록 수명주기를 확인한다.

`consultation_copy`는 관리자 “입력·저장·복사 상태”에 횟수와 세션 수로 표시한다. 현재 이 표는 이벤트 종류별 기간 집계이며 복사 위치별 보고서를 별도로 추가한 것은 아니다. 신청 링크는 계속 `/go/quote`와 `rel="sponsored"`를 사용한다. 분석 저장 실패나 지연이 있어도 공식 외부 링크로 이동하는 기존 동작을 유지한다.

## 대표 5페이지 성능 관측

2026-09-10 11:42:56–11:43:55 KST의 최초 비교 원자료는 [개편 전 JSON](../output/conversion-redesign/performance-baseline-normal.json)과 [개편 후 최초 JSON](../output/conversion-redesign/performance-final-first.json)에 보존한다. 개편 전 라벨은 `개편 전 6개 주제 이미지 빌드 URHjZCOFsbZj0MNZO9fzC`, 개편 후 최초 라벨은 `2026-09-10 전환 개편 + 도우미 높이/포커스 수정`이다. 이후 레이아웃 이동의 시점·원인 요소를 기록한 [최종 재관측 JSON](../output/conversion-redesign/performance-final-normal.json)과 독립 페이지 관측을 추가했다. 라벨은 수동 기록이며 측정 도구가 upstream 빌드를 자동으로 전환하거나 빌드 식별자를 검증하지는 않는다.

### 용량과 비교 조건의 해석

[측정 프록시](../output/conversion-redesign/qa-server.cjs)는 upstream 요청에 `Accept-Encoding: identity`를 사용하며 HTML에 계측 코드를 추가한다. 실제 JSON에서도 본문 `encodedBodySize`와 `decodedBodySize`가 동일하다. 따라서 표의 용량은 HTTP 압축이 없는 로컬 응답 기준이고, 운영 CDN의 Brotli·gzip 압축, 캐시 적중, 실제 다운로드 시간과 직접 비교할 수 없다. 브라우저 캐시는 비우지 않았지만 이번 10개 관측의 `zeroTransferCount`는 모두 0이다. 이것만으로 반복 방문이나 완전한 최초 방문의 비용을 대표한다고 판단하지 않는다.

공통 `NanumSquareNeo_Variable...woff2` 본문은 두 빌드 모두 **1,529,292바이트, 약 1.53MB**이며 각 페이지에서 한 번 요청됐다. 개편 후 홈을 제외한 4페이지 리소스 본문의 약 65–69%다. 홈에는 두 빌드 모두 약 1.77MB의 배경 영상 요청도 있어 폰트와 영상의 합이 개편 후 관측 용량의 약 84%를 차지한다. 새로운 글 이미지 10개 전체가 한 페이지에서 동시에 전송된 것으로 해석하면 안 된다. 이후 용량 개선 우선순위는 이 공통 폰트의 전달 방식·부분집합 구성과 홈 영상의 로딩 시점부터 검토할 수 있다.

개편 후 리소스 본문 증가는 페이지당 약 26–150KB다. 관측된 가이드·서비스 페이지 JS 합계는 약 518KB에서 538KB로 늘었고, 가이드 페이지 CSS는 약 74KB에서 87KB로 늘었다. 허브에는 링크 사전 요청 증가가, 설치 카테고리에는 글 이미지 썸네일 두 개가 포함된다. HTML 본문은 홈 32,198→67,019바이트, 실측 글 86,201→100,105바이트로 늘었다. 이 HTML 수치에도 프록시 계측 코드가 포함되므로 운영 전송량으로 제시하지 않는다.

관찰창 끝의 `initialImages.src`는 이미지 요소의 `src` 속성이다. Next Image의 최대 크기 fallback URL이 나타날 수 있어 실제 선택된 `currentSrc`나 다운로드 크기로 간주하지 않는다. 실제 요청 URL·본문 크기는 같은 JSON의 `observed.resources`에서 확인한다. 예를 들어 개편 후 실측 글은 해당 글의 최적화 이미지 한 개, 본문 19,786바이트가 이 관찰창에 요청됐다. 화면 아래의 지연 로딩 이미지까지 스크롤한 전체 페이지 사용량은 이 표에 포함되지 않는다.

## 배포 이후 28일 비교 평가 방법

### 비교 기간과 수집 조건

운영 반영일을 `D`로 기록한다. 반영 당일은 전후 코드가 섞일 수 있으므로 제외하고, 이전 28일은 `D-28`부터 `D-1`, 이후 28일은 `D+1`부터 `D+28`로 잡는다. 두 기간 모두 주중·주말이 네 번씩 포함된다. 관리자 통계는 KST 기준으로 고정한다. Search Console은 보고서의 날짜·필터·집계 기준을 기록하고 같은 도구 안에서 동일 조건의 두 기간을 비교한다.

이전 데이터가 없거나 당시 계측이 꺼져 있었다면 없는 데이터를 0으로 채우지 않는다. 새 `consultation_copy`와 신규 CTA는 이전에 존재하지 않았으므로 28일 동안 기준값을 확보하고 다음 28일에 같은 정의로 비교한다. 기존 문의 클릭은 전체 및 공통 페이지 집계로 전후 비교할 수 있다. 계측 재시도 개선으로 저장 누락이 줄어든 효과와 실제 행동 변화를 함께 고려한다. 지연 재전송 이벤트는 서버 수신일에 집계될 수 있다.

마지막 날의 자료가 아직 잠정 상태라면 확정 후 다시 내보낸다. 변경 영향을 확인하는 데 며칠에서 몇 달이 걸릴 수 있으므로 28일은 첫 검토 시점이며 순위 확정 시점이 아니다. [Search Console 잠정 데이터 안내](https://support.google.com/webmasters/answer/17011364?hl=en), [Google의 변경 후 트래픽 평가 안내](https://developers.google.com/search/docs/monitor-debug/debugging-search-traffic-drops)

다음 설정과 변경 이력을 함께 남긴다: 운영 반영 시각·커밋, canonical 도메인·공개 설정, 분석 활성화 및 장애 시간, 다른 홍보·광고 유입, 주요 콘텐츠 수정, 검색 색인 상태, 공식 사이트 전용 링크 적용 여부와 적용일. 28일 검토는 수동 평가 계획이며 자동 반복 작업을 생성한 것이 아니다.

복사 성공과 `/go/quote` 클릭은 실제 신청 완료가 아니다. `SITE_TRACKING_URL`, `SITE_TRACKING_FROM`, `SITE_TRACKING_CONFIRMED=true`가 모두 유효한 공식 사이트 전용 링크 설정이어야 사이트 실적을 구분한다. 기간 시작이 적용일 이후이고 오늘을 제외한 종료 기간이며 모든 날짜의 실적 입력이 완료되고 방문 조회가 성공해야 신청 전환율을 표시한다. 방문수가 0이면 비율을 표시하지 않는다. 이 값도 기간 합계 비율이며 방문자별·키워드별·유입 페이지별 신청 귀속을 의미하지 않는다. 현재 운영 설정의 충족 여부는 이번 작업에서 조회하지 않았다.

### 결과 기록과 다음 수정 결정

페이지·질문 그룹별로 `이전 값`, `이후 값`, `절대 차이`, `증감률`, `분모`, `데이터 누락`, `다음 조치`를 기록한다. CTR·문의 클릭률 등 비율의 차이는 %p로 표시한다. 이전 값이나 분모가 0이면 나눗셈으로 증감률을 만들지 말고 실제 건수와 “비교 기준 없음”을 쓴다. 적은 표본의 우연한 변동을 성공·실패로 단정하지 않는다.

전후 비교는 동일 방문자를 무작위 배정한 실험이 아니므로 검색 수요·계절·유입 구성·계측 개선의 영향을 분리해 단정할 수 없다. 한 번에 우선순위가 높은 페이지나 문제를 정해 수정하고 변경일을 남긴다. 자료가 부족하면 56일 또는 90일로 관찰을 이어가며, 검색 성과와 문의 경로의 증거를 함께 보고 다음 작업을 정한다.

## 남은 운영 작업

공개·검토 설정의 로컬 프로덕션 빌드·19페이지 HTTP 검사와 위 범위의 실제 브라우저 검증을 완료했다. 느린 복사 응답의 오래된 결과 처리 여부는 브라우저 실증이 남아 있다. 운영 Vercel 프로젝트의 비공개 화면 접근은 자동 승인 검토에서 거절된 상태이며 이번 변경을 운영에 배포하지 않았다. 필요한 승인이 확인되면 해당 프로젝트·변경 커밋·배포 상태를 확인하고 실제 도메인의 19페이지·robots·sitemap·canonical·이미지 응답을 검증한다.

이 문서에는 운영 검색 순위, 실제 문의 증가, 실제 신청·승인 증가를 확인한 결과가 없다. 최종 운영 반영일이 정해지기 전에는 28일 비교 시작일도 확정하지 않는다.
