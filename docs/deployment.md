# 배포와 운영

GitHub와 Vercel로 배포하려면 [Vercel 배포 준비](vercel-deployment.md)를 먼저 확인하세요. 운영 통계는 Neon PostgreSQL을 지원합니다. 설정과 현재 집계 정의는 [운영 통계 설정](analytics-setup.md)을 우선 확인하세요. 아래 영속 디스크 설명은 자체 호스팅 SQLite를 선택하는 경우에만 해당합니다.

## 1. 실행 환경

자체 호스팅 SQLite 방식은 **Node.js 22 LTS를 실행하는 단일 서버 + 영속 SQLite 저장소**를 기준으로 합니다. 운영 Neon 방식은 서버 전용 DATABASE_URL과 사전 스키마 초기화를 사용합니다. 웹 본문은 사전 렌더링되지만 이벤트·제휴 이동·관리자 API에는 Node 서버가 필요하므로 정적 파일 호스팅만으로 전체 기능을 제공할 수 없습니다.

- `better-sqlite3`는 네이티브 모듈입니다. 배포 대상 운영체제와 CPU 환경에서 `npm ci`와 빌드를 수행하세요. macOS에서 만든 `node_modules`를 Linux 서버에 복사하지 마세요.
- SQLite 파일·WAL·SHM이 같은 영속 디스크에 남도록 설정합니다. 서버를 재배포할 때 지워지는 임시 디스크는 통계 저장소에 적합하지 않습니다.
- 여러 컨테이너가 각자의 로컬 DB를 사용하면 통계가 나뉩니다. 이 버전에서는 한 앱 인스턴스를 실행합니다. 수평 확장이 필요해지면 중앙 DB와 공유 속도 제한 저장소로 변경해야 합니다.
- DB는 웹 공개 폴더 밖에 두고 앱 실행 계정만 접근하도록 권한을 제한합니다.

## 2. 환경변수

프로젝트의 `.env.example`을 참고해 `.env.local` 또는 호스팅의 비밀 환경변수를 설정합니다.

| 변수                   | 설정                                                             |
| ---------------------- | ---------------------------------------------------------------- |
| `NEXT_PUBLIC_SITE_URL` | 최종 HTTPS 도메인. 예: `https://curtain.example.com`             |
| `SITE_INDEXABLE`       | 검토·스테이징은 `false`, 공개 운영만 `true`                      |
| `DATABASE_PATH`        | 영속 디스크의 절대경로. 예: `/srv/masters-data/analytics.sqlite` |
| `ADMIN_PASSWORD_HASH`  | `npm run admin:setup`으로 생성한 scrypt 해시                     |
| `ADMIN_SESSION_SECRET` | 같은 명령이 생성한 서버 전용 세션 서명 키                        |
| `TRUST_PROXY`          | 제어하는 프록시가 `X-Forwarded-For`를 덮어쓸 때만 `true`         |

`NEXT_PUBLIC_SITE_URL`은 SEO URL과 브라우저 번들에 사용됩니다. 공개 도메인·`SITE_INDEXABLE`을 바꾼 뒤에는 **재빌드**하세요. 이벤트 API의 Origin 검사는 운영에서 설정 도메인과 정확히 일치해야 합니다. `www` 사용 여부·포트가 다르면 먼저 정규 도메인으로 리다이렉트하세요.

### 관리자 초기 설정

```sh
npm run admin:setup
```

터미널의 숨김 입력으로 12자 이상 비밀번호를 설정하면 해시와 무작위 세션 키를 출력합니다. 비밀번호는 저장하지 않으며, 생성값을 환경변수에 넣고 서버를 재시작해야 합니다.

**달러 기호 처리:** `.env.local`은 변수 확장을 사용하므로 생성 스크립트가 출력한 `scrypt\$...\$...` 형식을 그대로 저장합니다. 호스팅 대시보드나 프로세스 관리자가 환경변수를 직접 주입할 때에는 값이 실제 `scrypt$...$...`가 되도록 설정하고, dotenv용 백슬래시를 값에 포함하지 마세요.

해시가 유효하지 않거나 세션 키가 32자 미만이면 관리자 접근을 열지 않습니다. 로그인 후의 쿠키는 8시간 유효하며 운영에서 Secure·HttpOnly·SameSite=Strict입니다. HTTPS를 종료하는 리버스 프록시 뒤에서 실행하세요. 비밀번호나 세션 키를 교체할 때 둘 다 새로 생성하면 기존 로그인도 무효화됩니다.

## 3. 빌드와 서버 실행

### 일반 Node 배포

서버에서 프로젝트와 비밀 환경변수를 준비한 뒤 실행합니다.

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run start -- -p 3000
```

기본 서버는 `127.0.0.1`에서만 받습니다. 리버스 프록시를 통해 공개 HTTPS 도메인과 연결하고, 프로세스 관리자의 자동 재시작을 설정하세요. 다른 호스트 바인딩이 필요한 컨테이너에서는 `npx next start --hostname 0.0.0.0 -p 3000`을 사용합니다.

### Standalone 배포

`next.config.ts`의 `output: 'standalone'`이 최소 서버 산출물을 생성합니다. 공개 파일·정적 청크·포스트 파일도 함께 배포합니다.

```sh
npm run build
cp -R public .next/standalone/public
mkdir -p .next/standalone/.next
cp -R .next/static .next/standalone/.next/static
cp -R content .next/standalone/content
```

이미 해당 폴더가 있다면 내부에 중첩되지 않도록 배포 패키지를 새 디렉터리에서 구성하세요. 최종 산출물에서 `.next/standalone`을 실행 루트로 사용하고 런타임 비밀 환경변수를 주입합니다.

```sh
cd .next/standalone
HOSTNAME=127.0.0.1 PORT=3000 node server.js
```

`content/posts`는 공개 글 목록뿐 아니라 분석 API의 허용 경로 검증에도 쓰입니다. 파일을 누락하면 신규 포스트의 이벤트를 허용하지 않습니다. `public/fonts`와 라이선스 파일도 유지해야 한글 PDF가 작동합니다. `DATABASE_PATH`는 배포 폴더 밖의 절대경로로 지정하세요.

빌드 후 `ADMIN_HTTP_FIXTURE=true node --import tsx --test tests/admin-http.test.ts`로 standalone의 실제 HTTP 인증·CSV 응답과 모든 포스트의 파일 추적을 검증할 수 있습니다. 테스트는 빈 3004 포트에 자체 서버를 생성하고 자기 프로세스만 종료합니다. 임시 인증값은 메모리에서만 생성하며 기존 관리자 설정이나 고객 DB를 변경하지 않습니다. 빌드에 고정된 공개 Origin을 별도 백엔드 포트로 전달하는 프록시 구조를 모사합니다.

### 프록시와 캐시

- `/api/`, `/admin`, `/go/quote`, `/saved` 응답을 공유 캐시에 저장하지 마세요. 앱의 `Cache-Control`을 보존합니다.
- `/go/quote`의 리다이렉트를 캐시하거나 사전 방문하지 마세요. 모든 실제 이동 요청이 앱에 도착해야 통계를 기록합니다.
- 프록시가 전달하는 요청 본문에 크기 제한을 추가할 수 있습니다. 앱은 이벤트·로그인 본문을 최대 2KB로 제한합니다.
- `TRUST_PROXY=false`이면 요청 속도 제한은 프로세스 내 공통 버킷을 사용합니다. `true`를 쓰려면 신뢰하는 프록시가 외부의 임의 `X-Forwarded-For`를 제거하고 실제 클라이언트 주소를 넣어야 합니다. 앱 포트에 대한 직접 외부 접근도 차단하세요.

## 4. 공개·검색 등록

1. 검토 환경에서 `SITE_INDEXABLE=false`로 도우미·저장·PDF·제휴 URL·관리자 화면을 확인합니다. `robots.txt` 차단은 인증 기능이 아니므로 비공개 스테이징이 필요하면 별도의 접근 제한도 사용합니다.
2. 공개 도메인과 운영 정보를 확인하고 `NEXT_PUBLIC_SITE_URL` 및 `SITE_INDEXABLE=true`를 설정해 재빌드합니다.
3. 원본 HTML의 title·description·canonical과 공유 정보, `/robots.txt`, `/sitemap.xml`을 확인합니다. 사이트맵에 로컬 주소·관리자·보관함·개인 문서가 없어야 합니다.
4. Google Search Console에서 도메인 소유권을 확인합니다. DNS 방식이면 페이지 코드를 변경하지 않아도 됩니다. 사이트맵 URL을 제출하고 주요 대표 페이지의 수집 상태를 확인합니다.
5. 네이버 서치어드바이저에서 사이트 소유권을 확인합니다. 발급된 HTML 확인 파일을 `public/`에 두거나 발급 메타태그를 루트 메타데이터에 추가해 배포한 뒤 사이트맵을 제출합니다. 실제 발급값만 사용하세요.
6. 대표 페이지 7개와 관련 글을 페이지 단위로 평가합니다. 노출 부족·낮은 클릭률·낮은 도우미 완료율·낮은 문의 이동률을 구분해 개선합니다.

등록·메타데이터·구조화 데이터는 수집과 이해를 돕는 구성입니다. 특정 키워드의 상위 노출·색인·검색 결과의 형태를 보장하지 않습니다. 외부 소개 링크는 유용한 도우미·측정 자료를 참고하는 맥락으로 연결하고, 제휴 링크의 `rel="sponsored"`와 수수료 안내를 유지하세요.

## 5. 통계 운영과 한계

`/admin`에서 기간을 지정하고 CSV를 내려받습니다. 기간은 한국 시간의 시작일 00:00부터 종료일 다음 날 00:00 직전까지이며 최대 90일입니다. 현재 기본 기간은 28일입니다. 수동 신청·승인 실적도 같은 한국 시간 날짜로 입력합니다.

- 원본 이벤트는 180일 보관합니다. 저장소 접근 시 하루에 한 번 오래된 행을 정리합니다. 앱이 꺼져 있으면 다음 접근 때 정리합니다.
- 이벤트 ID의 SQLite 고유 제약으로 재전송을 중복 삽입하지 않습니다. 동일 클릭 ID의 제휴 리다이렉트도 한 번만 기록합니다.
- JS 없이 이동하면 서버가 방문 식별자를 새로 생성합니다. 브라우저에서 수집한 세션과 연결할 수 없으므로 이 이동을 도우미 완료 전환으로 단정하지 않습니다.
- 봇 User-Agent·prefetch·HEAD 요청을 제외하지만 모든 자동 트래픽을 판별하지는 못합니다. 공개 수집 API이므로 익명 이벤트 자체가 신원이나 계약 실적의 증명은 아닙니다.
- IP 원문은 DB에 넣지 않습니다. 속도 제한에는 메모리에서 해시된 요청 버킷을 사용합니다. 별도 프록시·호스팅 접근 로그의 보관은 인프라 설정에 따릅니다.
- 유입은 브라우저 referrer의 제한된 구분값입니다. 검색어·UTM 원문·원본 유입 URL을 저장하지 않습니다. 차단되거나 사라진 출처는 복원하지 않습니다.
- 서버가 문의 이동을 기록했다고 외부 페이지가 정상 열렸거나 신청이 완료됐다고 보장하지 않습니다. 외부 신청·상담 완료 측정은 제휴사의 공식 연동을 확보한 뒤 별도 이벤트로 설계해야 합니다.
- PDF는 브라우저에서 생성합니다. PDF의 제휴 링크는 외부 URL에 직접 연결되므로 사이트 리다이렉트 통계에 포함되지 않습니다.

브라우저 이벤트 큐는 sessionStorage에 최근 최대 60개를 남기며 네트워크 복구·페이지 재진입 때 다시 전송합니다. 브라우저 저장이 차단되거나 큐를 잃으면 복구할 수 없습니다. 실제 고객의 창 치수·문서 이름·PDF 내용은 통계 서버로 보내지 않습니다.

## 6. 백업과 장애 확인

SQLite WAL 모드에서는 실행 중인 `.sqlite` 파일 하나만 복사하면 최근 기록이 빠질 수 있습니다. SQLite의 온라인 백업 API를 사용하거나 앱을 정지한 뒤 DB와 관련 파일을 일관되게 보관하세요. 백업은 원본 180일 삭제 정책과 별개이므로 보관 기간도 설정합니다. 실제 복구는 별도 경로에 복원해 관리자 집계가 열리는지 확인합니다.

| 증상                             | 확인할 곳                                                         |
| -------------------------------- | ----------------------------------------------------------------- |
| 관리자 설정 필요 화면            | 해시 형식·달러 기호 확장·32자 이상 세션 키·서버 재시작            |
| 로그인 뒤 다시 로그인 화면       | HTTPS·Secure 쿠키·정규 도메인·세션 키가 서버마다 다른지           |
| 이벤트 API 403                   | Origin과 `NEXT_PUBLIC_SITE_URL`의 도메인·포트 일치                |
| 이벤트 API 400                   | 유형·카테고리·버튼 허용값과 실제 공개 포스트 경로                 |
| 이벤트 API 429                   | 요청 폭주와 프록시·`TRUST_PROXY` 설정; 프로세스 내 제한           |
| 이벤트 API 503 또는 통계 DB 오류 | 영속 디스크 연결·DB 경로·권한·남은 용량                           |
| 새 글의 통계가 안 쌓임           | `content/posts` 배포 포함 여부, 카테고리·파일명, 재시작           |
| PDF 한글·다운로드 오류           | `/fonts/NotoSansKR-Regular.ttf` 접근, 브라우저 오류·다운로드 정책 |
| 검색 노출이 모두 차단됨          | 빌드 시 `SITE_INDEXABLE=true`였는지, robots·메타데이터            |

DB 쓰기가 실패하면 이벤트 API는 503을 반환하고 브라우저 큐가 재시도를 준비합니다. 제휴 리다이렉트는 DB 장애에도 제공된 URL로 계속 이동합니다. 서버 로그에는 실패 종류만 남기고 고객 문서 내용을 출력하지 않습니다.

배포 후에는 홈페이지·주요 허브의 응답, 관리자 인증, 이벤트 API 오류율, 디스크 사용량을 확인하세요. 원격 제휴 양식에 시험 고객 정보를 전송하지 않고도 로컬 리다이렉트의 상태·Location 헤더를 검증할 수 있습니다.
