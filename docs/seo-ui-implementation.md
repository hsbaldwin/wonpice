## 검증 결과

- 프로덕션 빌드·TypeScript 검사: 통과.
- 공개 모드 실제 HTTP: 19페이지의 상태·고유 메타데이터·내부 링크·목차 앵커·Breadcrumb·Article·사이트맵 19개 검증 통과.
- 비공개 모드와 전체 회귀 테스트: 103개 통과, 실패 0개, 건너뜀 0개. 빈 사이트맵·noindex와 홈·관리자·DB 검증을 포함합니다.
- 콘텐츠·공통 UI·메타데이터 소스에서 사용자에게 금지된 한국어 표현이 남지 않음을 확인했습니다. 내부 영문 식별자는 유지했습니다.
- PostgreSQL 테스트는 PGlite의 실제 SQL 실행으로 집계·upsert·날짜 경계·중복을 확인했고 SQLite에도 같은 시나리오를 실행했습니다.
- Neon HTTP 드라이버의 네트워크 함수를 테스트 대역으로 교체해 무응답 상황을 만들고, 공식 신청 경로가 약 1.8초 후에도 정상 302를 반환하는 것을 확인했습니다. 테스트는 실제 네트워크나 가짜 운영 자격증명을 전송하지 않습니다.

### 화면 검증

브라우저에서 최종 공개 대상 19페이지를 각각 320·390·768·1440px로 검사했습니다(76개 조합). 관리자도 네 가지 너비로 별도 확인했습니다. 모든 공개 페이지에 H1이 하나씩 있었으며 페이지 전체 가로 넘침이나 14px 미만의 가이드 보조 문단이 없었습니다. 1440px 글 본문은 760px, 모바일 본문은 16px/28.8px 줄높이를 확인했습니다. 주요 신청·보조 행동은 56px/44px, 표의 첫 열은 sticky이며 키보드 포커스는 3px 테두리입니다.

모바일 목차를 Enter로 펼치고 링크를 Enter로 선택해 제목 앵커로 이동하는 것을 확인했습니다. 가이드 페이지는 즉시 앵커 이동을 사용하며 홈의 스크롤 방식은 유지합니다. 데스크톱은 사이드 목차, 768px 이하는 본문 안의 접이식 목차입니다.

JavaScript는 실제 서버 HTML을 스크립트 실행이 차단된 sandbox 프레임에서 검증했습니다. 본문·비교표·Breadcrumb·신청 링크와 기본 목차 펼치기가 작동했고, 홈에는 “도우미는 JavaScript가 필요합니다” 안내와 직접 문의 링크가 표시됐습니다. 관리자 실적 조회는 서버 렌더링, 입력·저장은 JavaScript 사용 흐름입니다.

홈은 임시 로컬 환경에서 240×180cm, 자연광·시선 보호를 입력·저장하고 새로고침 후 그대로 복원되는 것을 확인했습니다. 문의 링크가 `/go/quote?…cta=home-result`임을 확인했으며 외부 신청 양식은 제출하지 않았습니다.

관리자는 임시 로컬 계정과 DB로 로그인·오늘 조회·신청 3/승인 1 입력·신청 0으로 수정을 검증했습니다. 수정 후 한 행으로 유지되고 마지막 입력 시점이 갱신되며 공유 실적의 신청 전환율은 표시하지 않습니다. 이 숫자는 운영 실적이 아닙니다.

### 최종 실행 기록

- `npm run typecheck`: 통과. 최종 `next build`의 TypeScript 검사도 통과.
- `SITE_INDEXABLE=true` 로컬 빌드 + `tests/seo-http.test.ts`: 19페이지와 사이트맵 검증 통과.
- `SITE_INDEXABLE=false` 최종 로컬 빌드: 통과. 빈 사이트맵과 noindex 확인.
- `SEO_TEST_URL=http://127.0.0.1:3105 SEO_EXPECT_CANONICAL_ORIGIN=http://127.0.0.1:3105 ADMIN_HTTP_FIXTURE=true ADMIN_HTTP_PORT=3106 npm test`: **103개 통과 / 실패 0 / 건너뜀 0**.
- `npm run format:check`: 통과. 기존 `docs/media-sources.md`의 서식도 함께 정리했으며 내용은 유지.
- `git diff --check`: 통과.

실행 로그는 `output/seo-implementation/`에 보관했습니다(Git 제외).

HTTP 검증을 위해 로컬 빌드의 canonical만 임시로 `http://127.0.0.1:3105`를 사용했습니다. `.env.local`이나 운영 환경변수는 변경하지 않았습니다. 운영 빌드 전에 실제 도메인 설정이 필요합니다.

## 운영 연결 전 남은 작업

1. [운영 통계 설정](analytics-setup.md)에 따라 Neon `DATABASE_URL`을 설정하고 `npm run analytics:setup`을 실행합니다. 실제 Neon 연결·권한·네트워크·운영 지연은 이 환경에서 아직 검증하지 않았습니다.
2. 관리자 인증과 운영 HTTPS origin을 설정한 배포 환경에서 수집·조회·저장·로그인을 확인합니다. 사이트 전용 추적 링크는 공식 발급 이후에만 설정합니다.
3. 검색 공개 결정 후 `SITE_INDEXABLE=true`로 빌드·배포하고 Search Console·네이버의 수집과 검색 데이터를 확인합니다. 현재 작업은 검색엔진 실제 색인·순위를 입증하지 않습니다.

예약 작업, Search Console 등록, 실제 상담 신청, 운영 배포는 아직 수행하지 않았습니다. 운영 DB 스키마와 Vercel DB 환경변수 설정은 추가로 완료했으며 앱의 실제 연결은 배포 후 검증합니다. 사이트 정의는 [현재 사이트 구성 정의](site-definition.md), 설정은 [운영 통계 설정](analytics-setup.md)을 참고하세요.
