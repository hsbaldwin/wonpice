# 운영 통계 설정

구현일: 2026-09-09. Neon 운영 DB와 관리자 인증 연결 및 검색 공개 배포를 완료했습니다. 실제 방문·도우미 완료·문의 클릭 저장과 재배포 후 영속성을 확인했습니다. 최신 진행 기록은 [공개 및 운영 점검](release-runbook.md)을 참고하세요.

## Neon PostgreSQL 연결

1. Neon 프로젝트에서 운영용 데이터베이스와 접속 문자열을 준비합니다. 실제 신청자 개인정보를 이 DB에 넣지 않습니다.
2. 서버 환경에 `DATABASE_URL`을 설정합니다. `NEXT_PUBLIC_` 접두사를 붙이지 말고 Git이나 채팅에 접속 문자열을 남기지 않습니다. 로컬은 `.env.local`, Vercel은 해당 프로젝트의 Production 환경변수를 사용합니다. Preview는 별도의 테스트 DB를 권장합니다.
3. 같은 DB 설정을 가진 로컬 또는 배포 준비 환경에서 `npm run analytics:setup`을 한 번 실행합니다. 이 명령은 `.env.local`을 읽고 PostgreSQL 테이블·인덱스와 `landing_path` 열을 준비합니다. 재실행할 수 있고 기존 레코드를 삭제하지 않습니다. 초기화 과정에는 테이블 생성·변경 권한이 필요합니다. 초기화는 트랜잭션과 DB 잠금을 사용합니다.
4. `NEXT_PUBLIC_ANALYTICS_ENABLED=true`를 Config 유형으로 설정합니다. 브라우저 설정이므로 변경 후 빌드해야 합니다. 관리자 인증은 `npm run admin:setup -- --vercel`로 준비한 `ADMIN_PASSWORD_HASH`, `ADMIN_SESSION_SECRET`을 Production의 Secret 유형으로 설정합니다. 로컬 `.env.local`용 출력은 `npm run admin:setup`을 사용합니다. 기존 값을 이미 사용한다면 유지합니다.
5. `NEXT_PUBLIC_SITE_URL`을 실제 배포 도메인으로 설정합니다. canonical과 동일 출처 검증에 사용되며 **빌드 시점**에 고정됩니다.
6. 프로덕션 빌드 후 `/admin` 로그인, 이벤트 수집, 조회, 실적 입력·수정·CSV 내보내기를 확인합니다. 실제 상담 신청 양식은 테스트 제출하지 않습니다.

런타임은 `DATABASE_URL`이 있으면 Neon의 HTTP 드라이버를 사용합니다. Vercel에서 DB 설정이 없거나 실패하면 임시 SQLite로 대체하지 않습니다. 개발·자체 호스팅은 `DATABASE_URL`이 없을 때만 기존 `DATABASE_PATH` SQLite를 사용합니다. SQLite의 기존 이벤트는 보존되며 열을 추가합니다. 기존 SQLite 데이터를 Neon으로 자동 복사하지는 않습니다. 운영 이관이 필요하면 백업과 데이터 범위를 먼저 확정해야 합니다.

이벤트 저장 실패는 503으로 반환하여 클라이언트 재전송 큐가 같은 ID로 다시 보낼 수 있습니다. `/go/quote`는 저장 오류나 지연에도 공식 링크로 이동하며 약 1.8초 뒤에는 통계 대기를 종료합니다. 시간 초과 이벤트는 기록되지 않을 수 있으므로 대시보드는 완전한 트래픽 장부가 아닙니다. 알려진 봇·prefetch를 제외하고 중복 ID는 DB 기본키로 제거합니다. 최근 180일 이전 이벤트는 저장소 접근 시 하루 간격으로 정리됩니다. 수동 입력한 신청·승인 기록은 별도로 유지합니다.

## 집계 정의

| 항목           | 정의                                                            |
| -------------- | --------------------------------------------------------------- |
| 방문수         | 조회 기간 내 `page_view`가 있는 서로 다른 익명 세션 수          |
| 페이지 조회    | 조회 기간 내 `page_view` 이벤트 수                              |
| 문의 클릭수    | 조회 기간 내 서버가 기록한 `affiliate_outbound` 이벤트 수       |
| 문의 클릭률    | 같은 기간에 페이지를 조회하고 문의를 클릭한 세션 수 ÷ 방문수    |
| 도우미 완료율  | 기간 내 시작 이후 완료가 있는 세션 수 ÷ 기간 내 시작 세션 수    |
| 첫 방문 페이지 | 세션의 최초 페이지 기록 또는 해당 기록의 `landingPath`          |
| 유입 경로      | 세션의 최초 출처 기록. 검색어·전체 referrer URL은 보관하지 않음 |

모든 날짜 범위는 **한국 시간 00:00부터 다음 날 00:00 직전**입니다. 오늘·7일·28일·90일과 최대 90일의 직접 지정 범위를 지원합니다. 날짜가 잘못되면 최근 28일을 안내와 함께 표시합니다. 분모가 0이면 `—`로 표시합니다. 일별 방문수 합계는 기간 전체의 중복 제거 방문수와 다를 수 있습니다.

세션은 기존 `sessionStorage`의 브라우저 탭 단위 익명 UUID입니다. 30분 만료 세션이 아닙니다. 브라우저 저장 차단, 다른 탭, JavaScript 비활성 환경에서 집계가 달라질 수 있습니다. JS 없이 `/go/quote`로 이동한 클릭은 방문 세션과 연결되지 않아 클릭률 분자에서는 제외합니다. 이벤트 입력은 허용된 공개 경로와 이름·식별자만 받으며 이름·전화번호·주소·치수·자유 입력은 수집하지 않습니다. CSV는 KST 날짜별 집계만 제공하고 세션 ID를 내보내지 않습니다.

## 날짜별 신청·승인 입력

관리자 하단에서 날짜, 집계 범위, 신청·승인 건수를 입력합니다. 같은 날짜와 범위는 덮어써 수정합니다. 신청 건수는 신청일 기준, 승인 건수는 승인일 기준입니다. 승인일이 늦을 수 있으므로 승인 건수가 같은 날 신청보다 많아도 허용합니다.

확인된 0건은 직접 `0`으로 입력합니다. 빈 날짜는 **실적 미입력**이며 0건으로 가정하지 않습니다. 일부 날짜만 입력되었으면 부분 합계와 입력 일수를 표시합니다. 조회 실패 시 실적을 0건으로 표시하지 않으며 입력 폼도 숨겨 확인되지 않은 값을 덮어쓰지 않게 합니다.

`GET /api/admin/affiliate-results?from=YYYY-MM-DD&to=YYYY-MM-DD`는 인증된 범위 조회, `POST`는 JSON `{date, scope, applications, approvals}`를 받습니다. `scope`는 `shared` 또는 `site`입니다. 관리자 쿠키, 동일 Origin, 입력 필드·길이·정수 범위 검증을 적용합니다. 알 수 없는 필드나 미래 날짜는 거부합니다.

## 사이트 전용 실적 전환

현재 공식 링크는 여러 채널에서 공유하므로 **전체 채널 신청 실적**으로만 사용합니다. 이 수치를 방문수로 나누거나 페이지별 신청 실적으로 배분하지 않습니다.

공식 사이트 전용 링크를 새로 발급받은 뒤에만 아래 설정을 모두 사용합니다.

- `SITE_TRACKING_URL`: 공식 `https://dbdbdeep.com/ma/link.php?lncd=...` 형태의 전용 링크. 현재 공유 링크와 달라야 합니다.
- `SITE_TRACKING_FROM`: 실제 링크 전환일 `YYYY-MM-DD`(KST). 과거 공유 기간으로 소급하지 않습니다.
- `SITE_TRACKING_CONFIRMED=true`: 해당 링크가 사이트 전용임을 확인한 경우에만 설정합니다.

`/go/quote`는 적용일 전까지 기존 공유 링크를 사용하고 적용일 이후 전용 공식 링크를 사용합니다. 직접 링크 우회나 임의의 추적 코드는 만들지 않습니다. UI의 모든 신청 링크는 계속 `/go/quote`와 `rel="sponsored"`를 유지합니다. 설정이 없거나 형식이 잘못되면 기존 공식 공유 링크를 사용합니다.

사이트 실적 입력은 적용일부터 허용합니다. 기간 기준 신청 전환율은 기간 시작이 적용일 이후이고, 오늘을 포함하지 않는 종료된 기간이며, 날짜별 실적을 빠짐없이 입력하고, 방문 조회가 성공했을 때만 표시합니다. 방문수가 0이면 `—`입니다. 이는 **기간 합계의 비율**이며 방문자별·유입 페이지별 신청 귀속을 의미하지 않습니다. 실제 적용이 하루 중간이라면 다음 날부터 `SITE_TRACKING_FROM`을 설정해 공유 유입과 전용 유입을 섞지 마세요.

## 검색 공개와 배포

`SITE_INDEXABLE=false`가 현재 검토 기본값입니다. noindex, 전체 크롤링 차단, 빈 사이트맵을 함께 적용합니다. 운영 도메인·DB·관리자·공식 링크를 확인하고 공개 결정을 내린 후 `SITE_INDEXABLE=true`로 새로 빌드·배포하면 사이트맵에는 19개 공개 URL만 포함됩니다. `/admin`, `/api`, `/go`, `/saved`는 제외합니다.

검색엔진 색인과 노출은 별도 검증 대상입니다. Search Console·네이버에서 소유권, 사이트맵 제출, 대표 URL 검사와 검색어·노출·클릭률을 확인합니다. 공개 후 28일마다 검색 유입·문의 클릭과 분리된 신청 실적을 검토합니다. 예약 작업은 생성하지 않았습니다.
