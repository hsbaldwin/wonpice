# 홈 스크롤 스냅 레이아웃 진단

2026-09-06. 사용자의 한 화면 스냅 요구를 해석하고 구현을 측정한 기록입니다. 현재 첫 섹션·도우미는 이후 간결화 요청으로 다시 정리했으며, 최신 상태는 문서 마지막 절에 기록합니다. 아래 초기 진단은 패치 전 기록으로 보존합니다. 사용자의 패치 요청 이후 진행한 세 섹션 수정과 검수는 문서 하단에 추가했습니다.

## 확정된 표시 기준

섹션의 스크롤 스냅이 멈춘 위치에서 해당 섹션의 모든 콘텐츠가 한 화면에 동시에 보여야 합니다. 화면 높이는 브라우저의 콘텐츠 뷰포트이며 고정 헤더가 차지하는 높이를 제외합니다. 제목, 설명, 단계 목록, 링크와 버튼, 영상 제어와 하단 표시까지 포함합니다.

섹션의 배경만 화면 높이를 채우거나, 문서의 가로 넘침이 없거나, 추가 스크롤로 마지막 요소에 접근할 수 있다는 사실은 충족 판정의 근거가 아닙니다. 문구를 숨기거나 잘라내기, 내부 스크롤 추가, 전체 화면을 변환으로 축소하기도 이 요구를 충족하는 방법으로 간주하지 않습니다.

앞서 확인한 원래 콘텐츠 구성·문구·움직이는 영상 유지 및 비슷한 쉬폰 커튼·햇살 분위기의 고화질 영상 사용 기준은 계속 유효합니다. 레이아웃은 가로 폭과 세로 가용 높이를 함께 고려해야 합니다.

## 패치 전 원인

1. 공통 `.story-scene`의 `min-block-size`는 최소 높이만 정합니다. 콘텐츠와 상하 패딩 합계가 가용 높이를 넘으면 섹션이 더 길어집니다. 스냅은 그 긴 섹션을 정렬할 뿐, 내부 콘텐츠를 화면에 맞추지 않습니다. 헤더에 맞춘 `scroll-padding-top` 자체는 적용되어 있습니다.
2. 첫 섹션은 데스크톱에서 바깥 상하 여백 120px 이상, 콘텐츠 패널 패딩, 안내 박스 패딩, 안내 박스 아래 32px, 단계 사이 28px가 누적됩니다. 1280 × 720에서는 패널 524px와 바깥 패딩 120px가 가용 624px를 초과합니다.
3. 모바일 첫 섹션은 안내 박스·소개·세 단계가 세로로 쌓입니다. 390px에서는 콘텐츠 패널만 880px로 가용 높이 764px보다 크고, 바깥 여백 112px가 추가됩니다. 높이에 맞춰 밀도를 조절하는 규칙이 없습니다.
4. 도우미는 현재 긴 결과와 저장 기능을 같은 폼에 누적합니다. 코드상 여러 창 입력, 측정 설명 펼침, 검증 메시지 등도 높이를 늘립니다. 이 상태까지 한 화면을 요구하면 단계별 표시 또는 페이지 구성을 다뤄야 하며, CSS 높이 고정만으로 해결할 수 없습니다.
5. 공간별 가이드는 모바일에서 큰 4:5 사진 세 장과 제목·설명을 세로로 쌓습니다. 한 화면 기준에 맞추려면 사진과 텍스트가 나란한 행 등 공간 배분을 다시 정해야 합니다.

## 수정과 검수에 적용할 기준

- 첫 섹션은 기존 안내 박스와 설명·단계 구성을 유지하면서 중복 패딩과 간격부터 줄이고, 가용 높이에 따라 열 배치와 타이포그래피를 조정합니다. 하단 영상 제어 버튼의 높이와 안전 여백도 배분에 포함합니다.
- 도우미는 최초 입력뿐 아니라 선택·추천·추가 입력·설명 펼침 상태를 구분해 검사합니다. 한 화면 안에 표시할 정보의 단위를 다뤄야 하는 구조 변경을 첫 섹션의 색감·여백 보정과 혼동하지 않습니다.
- 실제 스냅 정지 후 각 표시 요소의 위쪽이 헤더 아래에 있고 아래쪽이 뷰포트 하단을 넘지 않는지 검사합니다. 부모 섹션의 높이만 맞춰 놓고 자식이 벗어나거나 겹치는 상태는 실패입니다.
- 이전 검수 기록의 ‘모바일 긴 내용은 자연 스크롤’은 최신 사용자 기준에서는 실패입니다. 초기 진단 시점의 구현을 한 화면 요구 충족으로 표시하지 않습니다.

## 패치 이후 첫 섹션 검수

첫 섹션의 `app/home.css` 전용 규칙을 수정했습니다. 화면 높이에 따른 패딩과 간격을 적용하고 중복 여백을 줄였습니다. 데스크톱 안내 박스·소개·세 단계 배치는 유지하며, 모바일은 같은 순서에서 단계 번호를 제목 옆으로 옮겼습니다. 짧은 가로 화면은 소개와 단계 목록을 두 열로 배치합니다. 하단 영상 제어 버튼은 최소 44px 높이와 안전 여백을 별도로 확보합니다.

본문은 데스크톱 16px, 모바일·짧은 가로 화면 14px입니다. 내용 숨김·잘림·내부 스크롤·전체 변환 축소를 사용하지 않았습니다. 최초 수정 전 첫 섹션 JSX와 비교해 기존 문구·버튼·콘텐츠 그룹이 동일함을 확인했습니다. 차이는 앞서 확정된 고화질 영상과 포스터 경로뿐입니다.

첫 섹션은 아래 9개 크기에서 각 요소가 헤더 아래·뷰포트 하단 안에 들어오는지 검사했습니다. 부모 섹션의 높이만 비교하지 않고 표시 콘텐츠 경계를 확인했습니다.

320 × 568에서는 실제 스냅 후 첫 섹션의 상단이 80px, 하단이 568px입니다. 화면 검토에서도 모든 기존 문구, 가이드 버튼, 영상 재생 제어가 잘리거나 겹치지 않고 표시됨을 확인했습니다.

## 도우미의 한 화면 단위와 검수

도우미는 현재 작업 패널의 제목·설명·입력·이동 버튼·보관함 링크·영상 제어가 한 화면에 들어오도록 구성했습니다. 공간 선택, 치수 입력, 측정 기준, 용도, 분위기, 추천 요약, 치수 확인, 대안, 상담 준비, 저장을 순서대로 전환합니다. 여러 공간과 창의 데이터는 유지하면서 현재 선택한 공간과 창 하나를 편집합니다. 모든 작업과 추천 내용을 한꺼번에 세로로 누적하는 구조를 바꾼 것이며, 내부 스크롤이나 잘림으로 길이를 제한하지 않습니다.

기존 도우미 소개 문구는 데스크톱에서 오른쪽 영상 위에 표시하고, 모바일에서는 **도우미 소개** 버튼으로 같은 내용을 한 화면 패널에서 엽니다. 측정 도움말, 브라우저 저장 안내, PDF·저장 알림도 별도 패널에서 확인하고 현재 작업으로 돌아갈 수 있습니다. 모바일 영상에 남아 있던 16:9 비율 규칙이 프레임을 가로로 늘리는 문제를 제거했고, 좁은 화면의 측정 기준 선택은 두 열로 배치해 하단 버튼과 겹치지 않도록 했습니다.

- **320 × 568:** 공간·치수·측정 기준·용도·분위기·추천 요약·치수 확인·대안·상담 준비·저장 패널을 모두 검사했습니다. 소개·측정 도움말·저장 안내·PDF 알림도 화면 안에 표시됩니다.
- **844 × 390 가로 화면:** 모든 주요 작업 패널과 도우미 소개의 표시 경계를 검사했습니다.
- **여러 창:** 20개 제한에서 추가 버튼이 비활성화되고 현재 창 하나만 편집됩니다. 공간 전환 시 창 선택이 첫 번째로 돌아가며 기존 375.5 × 240cm 치수는 보존됩니다. 첫 오류가 있는 세 번째 창으로 이동하고 해당 입력에 초점이 맞춰집니다. 20번째 창을 삭제하면 19개가 남고 선택 인덱스는 18로 정리됩니다.
- **여러 공간·보관:** 검수용 두 번째 공간을 삭제해도 첫 공간 데이터가 유지됩니다. 보관함 저장과 PDF 생성이 성공했습니다.

입력 변경 검수는 별도 `localhost` 출처에서 수행했습니다. 사용자가 사용하던 `127.0.0.1` 출처의 기존 작성 문서는 변경하지 않았습니다.
